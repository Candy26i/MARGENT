MARGENT：度量智能体系统中委派的边际价值

报告日期 2026-10-06 · 论文：NeurIPS 2026 投稿稿 · 代码：github.com/Candy26i/MARGENT

每个结果都标明来源：采集集＝训练题上强制展开的分支，用标准答案打分；开发集诊断＝开发池上按验证集选出的操作点；不相交评测＝与采集集不相交的评测（MedQA、MMLU-Pro、AQuA-RAT 为固定 checkpoint 后只跑一次的锁定评测，GPQA-Diamond 100 同时是它的开发池）。

1. 结论

一句话结论：另一个智能体值不值得调用，取决于它能否把当前这个候选答案从错改对。按这个边际价值来度量和学习委派，一次选对的调用就能拿到大部分可测得的增益，学到的策略每题只用约半次调用。

五条关键发现

  1. 可回收的价值集中在第一次选对的委派：Gain@1 宏平均 91.7%，第二次调用只多 0.5–4.5 分。采集集
  2. 一次调用的价值取决于调用谁：同一个 Reasoner 在 MedQA 净值 +6.8 pp，在 AQuA-RAT 是 −4.3 pp，Extractor 在四个任务上都接近零或为负。采集集
  3. 学到的策略在四个不相交评测上都高于自己的候选答案：宏平均 +17.1 pp，0.526 次调用 / 题；这是同一 scaffold 内的端到端差异，不是相对独立单模型基线的增益。不相交评测
  4. 约一次选择性调用 ≈ 三次强制调用：宏平均 73.2%@1.03 次 vs 73.6%@3.0 次，MMLU-Pro 持平，AQuA-RAT 反超 5.9 pp，GPQA 落后 6.0 pp。开发集诊断
  5. 候选答案本身对委派有用，只看结果的 RL 会学成「全都调用」：AQuA-RAT 上置空传给 Verifier 的候选答案，准确率 81.1% → 74.0%；只用结果奖励的 GRPO 继续训练走到 2.98–3.00 次调用 / 题，但没有准确率记录。开发集诊断

2. 方法

2.1 决策接口

系统里有一个可训练的 manager（Qwen3.5-9B）和三个冻结的子智能体；每一轮 manager 先写下候选答案，再二选一：提交，或委派给一个还没用过的子智能体。第 t 轮的状态是 s_t = (x, h_t, ŷ_t, U_t)（问题、交互历史、当前候选答案、已用过的子智能体集合），每个子智能体最多调用一次，所以一条轨迹最多 3 次委派。

u_t ∈ {commit} ∪ {delegate(a) : a ∈ A \ U_t}。（论文式 1）

表 R1. 三个子智能体。都冻结、贪心解码，只返回结构化的决策信号，不返回答案；修订候选答案和最终提交都由 manager 负责。
子智能体返回什么接收什么
Extractor与决策相关的事实及其极性问题与上下文
Reasoner问题分解、缺失的推理步骤问题与上下文
Verifier对当前候选答案的审计问题与上下文，加上 manager 当前的候选答案

2.2 边际价值的定义

Δ(s_t, a) = C(s_t, delegate(a)) − C(s_t, commit) ∈ {−1, 0, +1}。（论文式 2）

C(s_t, commit) 是直接提交当前候选答案是否正确；C(s_t, delegate(a)) 是强制委派给 a、让 manager 修订后立即提交这条分支是否正确。+1 是救回，0 是没变，−1 是损坏；它度量的是「调用、修订、提交」整个操作在固定修订协议下的效果，不是子智能体能力的内在度量。

2.3 同状态干预采集

  • 每道训练题先由温度 0 的 manager 不委派地生成根候选答案；从这个共同的根状态，强制「直接提交」和「委派给每个子智能体」。
  • 按广度优先枚举不重复子智能体的有序序列，最大深度 D ≤ 3；根错误时逐层评估，在首个出现成功的深度停止，并保留该层所有等长的成功序列。
  • 根正确时只评估一步委派，留作损坏分析；标准答案只用来给终端分支打分，从不展示给 manager 或子智能体。

2.4 边际价值蒸馏

表 R2. 蒸馏规则：三种根状态各给出什么监督目标（论文式 3、4）。
根候选答案采集到的分支蒸馏目标
正确只展开一步，用于损坏分析直接提交（Σ* = {ε}）
错误，在深度 d 首次出现成功停在深度 d，保留该层所有成功序列从最短成功序列中按该题固定的种子均匀抽一条：d 次调用后提交
错误，到深度 D 都没有成功所有层都评估完无标签（Σ* = ∅）：既不教提交，也不教委派

提交轨迹的数量被限制在救回轨迹数量的 ρ 倍以内（ρ 即提交/救回比，是数据构造超参数）；SFT 更新完整的 manager，所以候选答案到最终答案的增益是端到端的，不只是路由效应。

为什么不用每次调用惩罚

终端正确性奖励分不清「直接提交」和「多余的委派」，每次调用惩罚则引入一个随任务变化的准确率与资源之间的汇率。MARGENT 改用字典序偏好：先看正确，正确的里面再看调用少。

论文自己的限定

SFT 更新的是完整的 manager，所以这是同一 scaffold 内的端到端差异，不只是路由效应，不应读成相对独立单模型基线的增益；AQuA-RAT 上带工具 scaffold 的候选答案明显弱于直接作答提示。

在每题约一次选择性调用的操作点上，MARGENT 宏平均 73.2%@1.03 次，强制全部三个子智能体 73.6%@3.0 次：调用减到三分之一，准确率只低 0.4 分。MMLU-Pro 持平（71.5%），AQuA-RAT 反超（81.1% vs 75.2%），GPQA 仍落后 6.0 分。

4.5 调用差与提交/救回比 ρ开发集诊断

调用差 = P(委派 | 候选答案错) − P(委派 | 候选答案对)，在选出的开发集操作点上四个任务都为正：MedQA 0.381、MMLU-Pro 0.296、GPQA 0.067、AQuA-RAT 0.102。匹配预算重放（固定调用的角色和次数，题目随机重抽 2,000 次）中，MedQA 策略选中的子集达到 82.0%，高于随机区间 [75.0, 81.0]；MMLU-Pro 和 GPQA 在区间内。
