Overview

Agentic systems add sub-agents to improve answers. Each extra call costs computation and opens a new failure path: it can leave the answer unchanged or turn a correct answer into a wrong one. Existing selective methods decide from query features, team structure or model confidence. None of these compares committing against delegating from the same reasoning state. The paper asks a simple question: when is additional intelligence worth it?

MARGENT studies this in a concrete setting. A trainable manager writes the candidate solution it would submit now. It then commits or delegates to one of three frozen sub-agents (Extractor, Reasoner, Verifier), revises the candidate from the returned signal, and decides again. During data collection, MARGENT branches from the same manager-generated state into immediate commitment and every available delegation. It scores the terminal branches with the gold answer and reads off the marginal value of each call: rescue, no change, or corruption. It then distills the shortest successful branch into supervised trajectories and fine-tunes only the manager.

Across four reasoning benchmarks, the best single delegation recovers 91.7% of the accuracy gain available under the measured oracle. On four collection-disjoint evaluation sets (sets that share no examples with the interventional collections), the learned manager's final answer beats its own pre-delegation candidate by 17.1 points at 0.53 sub-agent calls per example. On development diagnostics (results on the pools used to select operating points), roughly one selected call matches forcing all three sub-agents on MMLU-Pro (71.5%) and beats it on AQuA-RAT (81.1% vs 75.2%).

The delegate-or-commit interface

For a question x, the state at turn t is st = (x, ht, ŷt, Ut): the question, the interaction history, the manager's current candidate solution, and the set of sub-agents already used. The manager policy πθ picks one action from

(1)ut ∈ U(st) = {commit} ∪ {delegate(a) : a ∈ A \ Ut}

A commit ends the trajectory and submits ŷt. A delegation appends the chosen sub-agent's output to the history; the manager then revises its candidate and chooses again. The interface allows any finite pool. The experiments use three sub-agents.

The three sub-agents in the experimental pool. All are frozen, greedy-decoded, and return structured decision signals rather than an answer.
Sub-agentWhat it returnsWhat it receives
ExtractorDecision-relevant facts and their polarityQuestion and context
ReasonerA decomposition of the problem and the missing reasoning stepsQuestion and context
VerifierAn audit of the current candidate solutionQuestion, context, and the manager's current candidate

Invariants

  • Sub-agents are frozen. Only the manager is trained.
  • Sub-agents emit structured signals, never a choice label or final answer.
  • Each sub-agent can be called at most once, so a trajectory has at most three delegations.
  • The manager owns both candidate revision and the final commitment.
  • The Verifier receives the candidate as input, so its cache key includes the candidate it audits. Cache keys for every sub-agent cover the complete input.
  • Teacher-synthesized sub-agent training data pass schema validation and explicit answer-leakage checks.

MARGENT

MARGENT has two stages. First it measures, from one manager-generated state, whether each delegation changes the correctness of the current candidate. Second it turns the shortest measured successful trajectory into supervision for a delegate-or-commit policy. Measuring whether more intelligence helps is kept separate from learning when to use it.

(a) Interventional marginal-value measurement

Let C(st, commit) ∈ {0, 1} say whether committing the current candidate is correct. A one-step probe forces the manager to delegate to sub-agent a, shows it the response, and then forces a revise-and-commit without further delegation. The marginal value of that call is

(2)Δ(st, a) = C(st, delegate(a)) − C(st, commit) ∈ {−1, 0, +1}

+1 is a rescue, 0 means no change in correctness, and −1 is a corruption. The value belongs to a state and a sub-agent together, not to the query or the sub-agent alone. It measures the whole delegation operation under the fixed revision protocol (call, revise, commit) and is not an intrinsic capability score for the sub-agent.

Collection works as follows.

  1. A temperature-zero manager produces the root candidate without delegation.
  2. From that shared root, the collector forces direct commitment and delegation to each sub-agent.
  3. Search is breadth-first over ordered sequences of distinct sub-agents up to a maximum depth D ≤ 3.
  4. For a wrong root, every sequence at the current depth is evaluated and search stops after the first depth that contains a success, so all equally short successes are kept. If nothing succeeds, search continues to depth D.
  5. For a correct root, only one-step delegations are evaluated; those branches are kept for corruption analysis.
  6. With three non-repeating sub-agents, the full ordered space has 16 sequences including direct commitment. The stopping rule does not require all 16 to be evaluated for every question; it evaluates only the layers needed to find the shortest successful depth.
  7. The gold answer only scores terminal branches and is never shown to the manager or the sub-agents.

Because root states come from the manager and descendant states come from forced interventions, the alternatives are compared from the same state, including actions the current policy would not choose on its own. This avoids estimating a sub-agent's value only on the examples the policy already delegates. Note that Eq. 2 is a one-step quantity: a first action with Δ = 0 under immediate commitment can still start a successful two-step continuation. Such an action is selected by the sequence rule below, not by its one-step Δ.

(b) Marginal-value distillation

For each collected root state, let Σ(s) hold the evaluated sequences, including the empty sequence ε (commit now), and let cσ ∈ {0, 1} be the final correctness of sequence σ. Equation 3 defines the set of shortest successful sequences Σ*(s). If the root is already correct, Σ*(s) = {ε}. If the root is wrong and at least one sequence succeeds, Σ*(s) is the set of all shortest successful sequences. Otherwise it is empty. Equation 4 then samples one trajectory uniformly from Σ*(s) with a fixed example-specific seed.

The three cases of the selection rule (Eq. 3 and 4).
Root candidateMeasured branchesSupervision target
CorrectOne-step branches only, kept for corruption analysisCommit immediately (ε)
Wrong, rescued at depth 1Search stops after depth 1; all one-call successes are keptOne call, then commit; one of the equally short successes, sampled with the example seed
Wrong, no success to depth DNeither a working delegation target nor a correct final answer was observedNo label. The state is dropped rather than taught to commit

Each selected trajectory yields a supervised decision at every visited state plus a final commit target. To keep directly correct examples from dominating the training set, commit trajectories are capped at ρ times the number of rescue trajectories. ρ is a data-construction hyperparameter and is swept in the experiments. SFT updates the full manager, not only a routing decision, so training can change which action is chosen and how the candidate is revised after a call. Any gain from candidate to final answer is therefore an end-to-end effect, not a pure routing effect. Collection happens once, before SFT; branches are not regenerated with the updated manager.

Why not a per-call penalty

The rule imposes a lexicographic preference over measured successful trajectories: correctness first, then fewer delegations. A scalarized call penalty needs a numeric exchange rate between accuracy and calls, and that rate is task-dependent. The trajectory target needs none. ρ still controls how much direct-commit supervision is retained.

5aHow much value is available after one delegation?

Most of the recoverable value is concentrated in the first delegation, provided it is chosen well. A single call captures over 90% of the measured gain on three tasks and 91.7% in the macro mean. A second call adds between 0.5 and 4.5 points. The third call adds exactly zero on the two collections searched to depth three. So on three tasks the first call is effectively the whole budget. GPQA is the exception: its second call adds 4.5 points, and its commit accuracy is the closest to chance, so a second opinion still has more to add there. Choosing the first call well is therefore the dominant decision in this pool.

5bThe value of a call depends on which sub-agent is called

The Verifier has the largest mean value on all four tasks, but the value of a call varies widely with role and task. The paper measures this with the mean one-step marginal value 100·Δ̄a from the forced one-step branches, which separates sub-agent choice from generic extra computation (the oracle picks a sub-agent after seeing branch outcomes). The same Reasoner is worth +6.8 points on MedQA and −4.3 on AQuA-RAT. The Extractor is near zero or negative everywhere. The Verifier is still not interchangeable with the other roles: 12 MedQA and 9 MMLU-Pro questions are rescued by the Reasoner and not by the Verifier, and forcing the strongest role on every question still spends calls on already-correct candidates.

These averages show why task-level routing is not enough. "Always call the Verifier" is a good rule at the task level. It has no way to say "stop here" for a given state, and it misses the minority of candidates that only another role repairs. At the MMLU-Pro and GPQA operating points the paper calls shallow, the trained policy never picks the Extractor, whose value is near zero. The distilled labels thus recover part of the role ordering, and the policy sees no gold labels at inference time.

5dFewer calls at the same accuracy

The paper reports MARGENT at four named sets of development operating points: low-call (Table 4), selected (Table 5), high-call (Table 8) and representative (Table 7). They are not all the same checkpoints; for example the GPQA high-call point (1.110 calls, Table 8) differs from the GPQA selected point (1.040 calls, Table 5). The paper does not list which checkpoint each set uses.

Against the strongest single role, MARGENT saves 43.5% of calls for about 1.6 accuracy points (Table 4). Because Table 2 names the Verifier the strongest average role, always calling it is a more informative baseline than no calls or all calls. On the four development pools, low-call MARGENT policies use 0.565 calls per example against the always-Verifier baseline's 1.00 and score 69.3% against its 70.8%. The paper gives the average accuracy cost as 1.6 points; the rounded macro row shows 69.3 vs 70.8.

At about one selected call, MARGENT matches forcing all three sub-agents (Table 5). The selected operating points average 73.2% at 1.03 calls; force-all averages 73.6% at 3.0 calls. That is a threefold cut in calls for a 0.4-point difference. The difference is concentrated on GPQA, where force-all stays 6.0 points better; on MedQA the gap is 1.5 points. MMLU-Pro is the cleanest case: 1.07 selected calls match three forced calls at 71.5%. AQuA-RAT shows that more calls can hurt: 1.03 selected calls reach 81.1%, force-all 75.2%.

Rescue and corruption under the learned policy

Accuracy hides two opposing effects of delegation. Table 8 splits each high-call operating point into two shares of all examples: candidates that were wrong and end correct (correction, the paper's word for a rescue produced by the learned policy), and candidates that were correct and end wrong (corruption). Net value is positive for every policy, but the two shares are balanced very differently across tasks. AQuA-RAT corrects 48.0% of all examples and corrupts 2.4%, a twenty-to-one ratio. GPQA corrects 19.0% and corrupts 4.0%. A high oracle therefore does not by itself justify calling every sub-agent: the oracle keeps only successful branches, while an executable policy pays for its own mistakes.

5eDoes the policy call on the right states?

For analysis only, gold labels give the call gap: the probability of delegating when the candidate is wrong minus the probability when it is correct. The paper reports the gap at development operating points it calls selected. These are not necessarily the Table 5 points: Table 9 lists a MedQA point with the Table 5 values (85.0%, 1.000 calls) and a call gap of .000, while the MedQA gap reported here, 0.381, appears in Table 9 at the depth-1, ρ = 2 point (82.5%, .560 calls) confirm which checkpoints the call-gap values refer to. At those points the gap is positive on all four tasks: 0.381 on MedQA, 0.296 on MMLU-Pro, 0.067 on GPQA and 0.102 on AQuA-RAT. The small GPQA gap matches its weaker policy result: when candidates are hard to tell apart, the manager drifts toward indiscriminate calling. Across the representative points in Table 7, the gap is smallest on GPQA (0.017) and AQuA-RAT (0.152) and larger on MMLU-Pro (0.225) and MedQA (0.291). This is a descriptive pattern, not a causal relation: selective calling looks harder when the candidate is near chance.

A positive gap by itself does not show that the policy predicts the marginal value of a specific sub-agent. The paper adds a stricter test, a matched-budget replay: hold the role and the number of calls fixed, then resample which examples get called, 2,000 times. MedQA's selected subset scores 82.0%, above the random 95% interval [75.0, 81.0]. MMLU-Pro (59.5% vs [54.0, 60.5]) and GPQA (51.0% vs [44.0, 53.0]) stay inside their intervals. The strongest better-than-random evidence is therefore on MedQA. The test does not separate candidate use from query difficulty.

5fCommit examples control the call-stop trade-off

Within each pair of Table 9 the commit-to-rescue cap ρ is the only data-construction variable that changes. Keeping more commit examples lowers the call rate in every pair. The call gap generally rises at the same time, so the remaining calls concentrate on wrong candidates. Accuracy, however, is not monotone. The aggressive AQuA-RAT comparison removes 37.4% of calls and loses 12.6 points. ρ is a transparent control over policy behaviour, not a free efficiency gain.

5gDoes the candidate matter to a delegated call?

If marginal value is state-specific, then what a sub-agent is handed should change what it is worth, independent of the question. The paper tests this on AQuA-RAT with the ρ = 0 checkpoint, which delegates on every example. Blanking only the current_solution argument passed to the Verifier, with no retraining and no change in call budget, lowers accuracy from 81.1% to 74.0%. Correction falls from 0.480 to 0.409 while corruption is essentially unchanged. The candidate is thus a useful object for a delegated call to audit. Routing was fixed in this run, so the ablation does not by itself show that the router uses the candidate when deciding whether to call.

Appendix diagnostics

Two sets of results in the paper's appendix explain design choices. Neither is a main comparison.

(a) Outcome-only GRPO collapses to three calls

Appendix D records two GRPO continuations that start from selective SFT checkpoints and use a terminal binary correctness reward with no call penalty. Both converge to the three-call ceiling: 2.98 calls per example for the MedQA 8B manager and 3.00 for the 9B manager. Accuracy records for these two runs are missing from the exported record and are not imputed, so the appendix supports a claim about call behaviour, not about the accuracy cost of the collapse. For reference, Figure 8 draws the selective SFT MedQA three-seed mean of 0.517 calls (Table 4) and the Table 3 macro mean of 0.526.

The Appendix D 8B run in the released snapshot

The supplementary snapshot contains a Qwen3-8B GRPO run (results/medqa_marginal_v1/, checkpoint grpo_binary_mv2) whose mean test calls, 2.985, match the 2.98 of the "MedQA, 8B manager" row. The paper does not name the run, and the accuracy records of the Table 10 runs are absent from its exported record, so the accuracies below come from the snapshot only. On the 200 dev questions: candidate 55.5%, final 67.5%, 3.000 calls per question, 36 candidates corrected, 12 corrupted, exact McNemar p = 7.2e-4 against the candidate. On the 200 test questions: candidate 63.5%, final 76.5%, 2.985 calls, 38 corrected, 12 corrupted, p = 3.1e-4. Its call rate is 100% for both wrong and correct candidates, so the call gap is 0. The sub-agents help; the manager simply never learned to stop.

The same snapshot holds the one-step interventional collection of that run (400 MedQA training questions, depth 1): direct 55.0%, forced Extractor 58.5%, forced Reasoner 78.8%, forced Verifier 84.5%, hindsight best one-step branch 91.0%; rescued/corrupted counts 25/11, 100/5 and 127/9. Those 400 questions overlap the sub-agent SFT questions (400/400; the collection command lacked --exclude_sft_example_ids), so its rescue rates are likely inflated. The dev and test traces do not overlap the SFT questions. This run is not the selective SFT policy of the main text.

(b) Predecessor scaling diagnostic

Before the marginal-value experiments, the authors evaluated cold-start, generic and task-specific multi-agent training variants on three of the four final tasks. Backbones were Qwen3-4B, Qwen3-8B and Qwen3.5-9B; development sets held 100 to 200 examples per task. Table 6 lists, for each task and size, the best variant minus the base model of the same size. The macro gain drops from +20.0 at 4B to +4.8 at 9B, and on GPQA the 9B gain is exactly zero. Since each cell takes a maximum over several variants on a small sample, the table shows the tension that motivated the work. It is not a scaling law and not a main comparison. The lineage also explains the method: outcome-only GRPO and extra sub-agent SFT did not reliably improve the earlier pipeline, while manager-side cold-start SFT improved most cells. That motivated the controlled same-state collection.

Limitations and scope

The list follows the paper's own scope statements and its checklist answers.

  • Fixed three-agent pool. All results use Extractor, Reasoner and Verifier. Force-all uses the recorded scaffold order; no sub-agent order sweep exists.
  • Mostly single runs. Only one MedQA SFT configuration was replicated with three additional seeds (80.5 ± 1.0 accuracy, 0.517 ± 0.043 calls). Every other task-level comparison is a single run, so the paper reports no comprehensive error bars or significance tests.
  • Development diagnostics vs locked evaluations. Tables 4, 5, 7, 8 and 9 are operating points selected on the development pools. Only Table 3 is a locked evaluation, and GPQA-Diamond-100 doubled as its development (diagnostic) pool.
  • Forced-Verifier baseline is not candidate-matched. The recorded implementation does not pass the same pre-call candidate to the Verifier.
  • End-to-end, not routing-only. SFT updates the full manager, so candidate-to-final gains mix routing and revision. The paper reports no independently prompted single-model baseline; on AQuA-RAT it states that the scaffold candidate is much weaker than a plain-answer prompt.
  • No token or latency numbers. These were not collected. Resource use is stated only in sub-agent calls.
  • Exported record is incomplete. Optimizer settings, hardware, synthesis prompts, LoRA configuration, stable example ids and per-example outputs for paired confidence intervals are absent. The checklist answers "No" to full reproducibility details, statistical significance and compute resources.
  • GPQA is near chance. The candidate is 17 points above 1/K, the call gap is close to indiscriminate calling, and the sample is too small to resolve a small difference. Selectivity is weakest there.
