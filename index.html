MARGENT

Measuring the Marginal Value of Delegation in Agentic Systems

Paper (PDF) Code Experiment report (中文) Results data (JSON)

Overview

Agentic systems add sub-agents to improve answers. Each extra call costs computation and can leave the answer unchanged or turn a correct answer into a wrong one. Existing selective methods decide from query features, team structure or model confidence; none compares committing against delegating from the same reasoning state. The paper asks when additional intelligence is worth it.

MARGENT uses a trainable manager that writes the candidate it would submit now, then commits or delegates to one of three frozen sub-agents (Extractor, Reasoner, Verifier), revises the candidate from the returned signal and decides again. During collection it branches from the same manager-generated state into immediate commitment and every available delegation, scores the terminal branches with the gold answer, and reads off the marginal value of each call: rescue, no change or corruption. It then distills the shortest successful branch into supervised trajectories and fine-tunes only the manager.

The delegate-or-commit interface

For a question x, the state at turn t is st = (x, ht, ŷt, Ut): the question, the interaction history, the manager's current candidate solution and the set of sub-agents already used. The manager picks one action from Eq. 1; a commit submits ŷt and ends the trajectory, while a delegation appends the chosen sub-agent's output to the history, after which the manager revises its candidate and chooses again.

Invariants

  • Sub-agents are frozen. Only the manager is trained.
  • Sub-agents emit structured signals, never a choice label or final answer; the Verifier additionally receives the manager's current candidate as input.
  • Each sub-agent can be called at most once, so a trajectory has at most three delegations, and the manager owns both candidate revision and the final commitment.

MARGENT

(a) Interventional marginal-value measurement

(2)Δ(st, a) = C(st, delegate(a)) − C(st, commit) ∈ {−1, 0, +1}

C(st, commit) says whether committing the current candidate is correct, and C(st, delegate(a)) is the correctness of a branch that forces one delegation to a, lets the manager revise, and then commits without further delegation. +1 is a rescue, 0 means no change and −1 is a corruption; the value measures the whole call-revise-commit operation under the fixed revision protocol, not the intrinsic capability of the sub-agent.

  • A temperature-zero manager produces the root candidate without delegation; from that shared root the collector forces direct commitment and delegation to every sub-agent.
  • Search is breadth-first over ordered sequences of distinct sub-agents to a maximum depth D ≤ 3; for a wrong root it stops after the first depth that contains a success and keeps all equally short successes.
  • For a correct root only one-step delegations are evaluated, kept for corruption analysis; the gold answer scores terminal branches only and is never shown to the manager or the sub-agents.

(b) Marginal-value distillation

The three cases of the selection rule (Eq. 3 and 4).
Root candidateMeasured branchesSupervision target
CorrectOne-step branches only, kept for corruption analysisCommit immediately (ε)
Wrong, first success at depth dSearch stops at depth d; all successes at that depth are keptOne of the shortest successes, sampled with a fixed example seed: d calls, then commit
Wrong, no success to depth DEvery layer evaluated, none succeedsNo label (Σ* = ∅): the state teaches neither commit nor delegate

Commit trajectories are capped at ρ times the number of rescue trajectories, where ρ is a data-construction hyperparameter, and SFT updates the full manager, so candidate-to-final gains are end-to-end effects rather than routing-only effects.

Why not a per-call penalty

The rule imposes a lexicographic preference over measured successful trajectories: correctness first, then fewer delegations. A scalarized per-call penalty needs a task-dependent exchange rate between accuracy and calls; the trajectory target needs none, and ρ still controls how much direct-commit supervision is kept.

Caveat: end-to-end, not routing-only

SFT updates the full manager, so Table 3 is an end-to-end difference inside the same scaffold, not a routing-only effect or a gain over an independently prompted single model; on AQuA-RAT the tool-enabled scaffold's candidate is much weaker than a plain-answer prompt.

At about one selected call per example, MARGENT averages 73.2% at 1.03 calls against 73.6% at 3.0 calls for forcing all three sub-agents; MMLU-Pro matches at 71.5% (1.07 vs 3 calls), AQuA-RAT is 5.9 points better (81.1% vs 75.2%) and GPQA stays 6.0 points worse. That forced-Verifier baseline did not receive the candidate, so it is a strong operational baseline rather than a matched routing ablation.

5eDoes the policy call on the right states? development diagnostic

For analysis only, gold labels give the call gap (the probability of delegating when the candidate is wrong minus the probability when it is correct), which is positive on all four tasks at the selected development operating points: 0.381 on MedQA, 0.296 on MMLU-Pro, 0.067 on GPQA and 0.102 on AQuA-RAT. A matched-budget replay that fixes the role and call count and resamples examples 2,000 times puts MedQA's selected subset at 82.0%, above the random 95% interval [75.0, 81.0], with MMLU-Pro and GPQA inside their intervals, although this test does not isolate candidate use from query difficulty.
